### Routing engine (`candidates.py`)

Pure function `generate_candidates(origin, destination, max_stops=1, include_train=True)` returns `list[Itinerary]`. Four stages, all incremental:

1. Direct flight (always)
2. 1-stop via valid transit hubs (`max_stops >= 1`, filtered by `TRANSIT_REGIONS`)
2b. 2-stop via different-region hub pairs (`max_stops >= 2`, no same-region backtracking)
3. Train + fly (CKG origin only), with a longhaul train+1-stop extension for EUROPE / NORTH_AMERICA destinations

`TRANSIT_REGIONS` is a `frozenset`-keyed dict — the **most important business logic in the project**. Without it, every CKG → VIE search would suggest routings via Bangkok or Manila.

### Live fli integration — three drift bugs found and fixed

Task 9's probe (see `scripts/probe_fli.py`) caught:

1. **`MaxStops.NONE` doesn't exist.** Renamed to `MaxStops.NON_STOP`. Without this, every `_real_fli_search` call raised `AttributeError`.
2. **`best.airline` is always `None`.** Airline lives at `result.legs[0].airline` as an `Airline` enum. Without this, airlines silently showed "Unknown."
3. **`best.price` is in arbitrary local currency**, not USD. Test query CKG→BKK returned `24414.0 JPY` — silently treating that as USD produced a ~150x mispricing. Fixed by changing the return shape to `{"price", "currency", "duration_min", "airline"}` and routing through `currency.convert_to_display(amount, from_currency)`.

A fourth bug surfaced during manual verification against Google Flights:

4. **fli returns `price=0.0` for many intra-China and China-exit legs** (SGN→CKG, HAN→CKG, HKG→CKG when CNY-priced). Without a guard, these silently summed as zero into multi-leg totals — Brendan caught DAD→SGN→CKG showing C$84 vs Google's C$410. Defensive fix: `if not best.price or float(best.price) <= 0.0: return None`. Itineraries with unpriceable legs are now excluded from rankings.

### Environment fix — Python 3.14 SSL + Frankfurter User-Agent

After flipping `USE_MOCK = False`, the FX provider (Frankfurter) was unreachable on Brendan's venv. Two compatibility shims in `currency._fetch_rates_from_api()`:

- Python 3.14 on macOS doesn't trust the system CA bundle by default — patched to use `certifi.where()` explicitly.
- Frankfurter rejects `Python-urllib/3.14` user-agent with HTTP 403 — added `User-Agent: flight-router/1.0`.

After this fix, FX loads live and caches to `.fx_cache.json` for 24hr as designed.

### `format_results` refactor — anchor adapts to sort mode

Originally always anchored on the absolute-fastest itinerary, even when sorting by cost. The fastest often wasn't in the displayed top_n, so no row showed a clear `(fastest)` anchor and the savings/hr numbers compared against an invisible reference. Brendan flagged this as confusing.

New behavior:
- `sort_by="cost"` → row 1 = cheapest, labeled `(cheapest)`. Column "extra/hr" = extra cost per hour saved.
- `sort_by="duration"` → row 1 = fastest, labeled `(fastest)`. Column "savings/hr" = savings per extra hour.
- Strictly-worse rows show `—` instead of negative numbers.
- An intent line above the table explains the column in the current sort mode.

## Open question — GUI design

Brendan's explicit direction: **terminal-only is not the destination.** The CLI is a stopgap. Documented in CLAUDE.md as `Immediate next steps #1`, in README.md `Future additions`, and in the user-memory file at `~/.claude/projects/-Users-bsingbeil-Sites/memory/project_flight_router.md`.

**My proposed shape (awaiting his approval):**

- **Stack:** Flask + Jinja2 templates. One Python file (`app.py`), one HTML template (`templates/index.html`). One new dependency (`flask>=3.0`). No JavaScript framework.
- **Two routes:** `GET /` renders the search form. `POST /search` runs the pipeline and re-renders the page with the form + results table below.
- **Visual:** Reuses the paper/ink aesthetic from `README.preview.html` (Bricolage Grotesque + Fragment Mono, cream background, cranberry accents).
- **Behavior:** Loading state during fli calls (~30-60s for a CKG → VIE search). Results table mirrors CLI: anchor row labeled, savings/hr column adapts to sort mode, failed-pricing count surfaces as a footnote.
- **Run:** `python app.py` → opens at `http://localhost:5050`.
- **Out of scope for first cut:** No background task queue (request blocks during fli). No history. No date-range search. No mobile-tuned layout.

Alternatives offered: FastAPI + JSON API, server-rendered with HTMX, full SPA. He hasn't picked one. **First action in next session: confirm shape, then build.**

## Known caveats (already documented in CLAUDE.md)

- **fli zero-price bug** drops some itineraries silently — primarily anything routing through Vietnamese hubs (SGN, HAN) and certain China-exit legs (HKG-CN when CNY-priced). Brendan's CKG → VIE use case routes through Middle East / East Asia hubs, which are unaffected.
- **fli rate-limiting (HTTP 429)** kicks in after ~30-50 rapid queries. With `MAX_CONCURRENT_QUERIES = 6` and 207-candidate searches you can hit it. Wait a few minutes between heavy searches. The fallback shows `(no complete pricings)` cleanly without crashing.
- **fli currency drift** — Google Flights returns prices in IP-geolocated currencies (often JPY for Asian queries). The pricer normalises via `currency.convert_to_display(price, native_ccy)`. If a price looks ~150x off, the source currency wasn't recognised — check `currency.TRACKED_CURRENCIES`.
- **Train data is hardcoded approximations.** Always verify on Trip.com or 12306 before booking a train leg.
